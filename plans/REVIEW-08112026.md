# Адверсариальное ревью UI/UX — Отчёт №08112026

(дата 2026-11-08, проект «Всетут», `client/src`)

## Резюме

Проверено: все 36 CSS-файлов в `pages/` и `components/`, соответствующие JSX, оба файла i18n (`en.json`/`uk.json`), токены `index.css`. Систематически прогнаны grep-поиски по hex-цветам, эмодзи, кириллице в JSX, `@media`, `px`-размерам шрифтов, фиксированным ширинам, `position/z-index`.

Всего зафиксировано **34 дефекта**:
- **КРИТИЧНО:** 4
- **СЕРЬЁЗНО:** 14
- **НЕЗНАЧИТЕЛЬНО:** 16

Самые критичные проблемы:
1. **Кислотные vivid-палитры** (`#00c6ff`, `#ff416c`, `#ff52a2`→`#9b36d9` и т.п.) — выставляются пользователю как штатная опция «насыщенный стиль».
2. **Названия 3 из 7 палитр не переведены** — `ocean/sunset/lavender` остаются по-английски («Ocean Breeze», «Sunset Vibes», «Lavender Sky») даже в украинском интерфейсе, тогда как остальные 4 переведены → разнобой языка в одном списке.
3. **Захардкоженный текст цвета `#243` на пользовательском цвете смены** (`Work.css:303`) — если пользователь выберет тёмный цвет смены, текст чипа станет нечитаемым.
4. **Массовый захардкоженный hex мимо токенов** в Work/Study/Cycle/Finance/Food/Notes — часть не переопределена для тёмной темы, что ломает единство тем.

Честно слабые оси (доказательств мало): **ПЕРЕКРЫТИЕ** (z-index аккуратно эшелонирован: overlay=60, модалки=50, тултипы=200 локально; конфликтов не найдено) и частично **КОНТРАСТ текста-на-акценте** — разработчики осознанно развели `--color-on-accent` по стилю/палитре (`index.css:250-269`), так что вопиющего «светлое на светлом» на кнопках нет.

## Ось 1. ЧИТАБЕЛЬНОСТЬ / КОНТРАСТ

**[КРИТИЧНО] `Work.css:303`** — текст чипа смены захардкожен тёмно-зелёным на фоне, который пользователь выбирает сам:
```
.work-cal-chip { … font-size: 0.66rem; … color: #243; … }
```
Фон чипа (`--color` типа смены) задаётся пользователем в палитре смен. Если выбрать тёмный/насыщенный цвет смены — `#243` (почти `#224433`) сольётся в нечитаемое пятно. Цвет текста обязан зависеть от яркости фона, а не быть константой.

**[НЕЗНАЧИТЕЛЬНО] `index.css:76` / `index.css:117`** — muted-токены пограничны по WCAG: светлый `--color-text-muted: #6b7280` на белом ≈ 4.83:1 (едва проходит AA для обычного текста и проваливается, когда применяется к мелким 0.64–0.8rem подписям вроде `Work.css:304 .work-cal-more` и `Food`/`Study` мета-строк). При использовании muted поверх тонированных поверхностей (`--pill-bg`, `--color-surface-2`) контраст падает ниже 4.5:1.

**[НЕЗНАЧИТЕЛЬНО] Честно:** вопиющего «светлое на светлом» на основных кнопках нет — `index.css:250-269` осознанно переключает `--color-on-accent` (#fff для vivid + тень, тёмный для pastel, спец-override для green/amber vivid). Это сделано грамотно, обвинение по «тексту-на-градиенте» снимается.

На 320–480px эти экраны полагаются только на flex/grid-перенос; фиксированные внутренние ширины (ниже) дадут горизонтальный скролл.

**[СЕРЬЁЗНО] Фиксированные px-ширины в таблицах/колонках без гарантии переноса:**

**[НЕЗНАЧИТЕЛЬНО / смягчено] `Study.css:757 .study-grid { min-width:640px }`** — сетка расписания шире мобильного экрана, НО обёрнута в `.table-scroll { overflow-x:auto }` (`Study.css:213`), применённый к `.data-table`. Горизонтальный скролл локализован в контейнере — вёрстка страницы не рвётся. Обвинение частично снимается; риск только если конкретный экземпляр не внутри `.table-scroll`.

## Ось 3. ЗУМ / МАСШТАБ

**[СЕРЬЁЗНО] Мелкие шрифты в жёстких rem ниже порога читабельности** (`Work.css`):
```
:303 .work-cal-chip   font-size: 0.66rem;   (~10.6px)
:304 .work-cal-more   font-size: 0.64rem;   (~10.2px)
:305 .work-cal-toomany font-size: 0.62rem;  (~9.9px)
```
Это ниже рекомендованных 12px; хотя rem масштабируется при зуме браузера, базовый размер слишком мал для календарной плотной сетки.

**[НЕЗНАЧИТЕЛЬНО] Жёсткие `px` в тексте** вместо rem: `Legal.css:22/40/84/94/100/117 (13–18px)`, `AuthForm.css:170 (13px)`, `Settings.css:407 (14px)`, `Footer.css:12 (13px)`, `HealthConsentGate.css:17 (36px)/:23 (20px)/:29/:51 (15px)`. При системном увеличении шрифта такие подписи не растут пропорционально телу. `index.css:340 font-size:16px` на корне — нормально (база), остальные `px` — нет.

**[НЕЗНАЧИТЕЛЬНО] `overflow:hidden` на элементах с текстом:** `Work.css:303` (`white-space:nowrap; overflow:hidden; text-overflow:ellipsis` при фикс-плотности) обрежет названия смен при увеличении шрифта.

**[СЕРЬЁЗНО] `Notes.css:51`** — карточки заметок жёстко `color:#33312b` и остаются светлыми в ОБЕИХ темах (фон — пастель из палитры). В тёмной теме набор ярких пастельных квадратов на фоне `#18181b` — это и глэр, и, при близких пастельных тонах, слабое различение карточек между собой (у `.note-card` нет `border`, только `box-shadow: var(--shadow-sm)`, строка 50 — на тёмном фоне тень почти не видна).

## Ось 6. ВЫРВИГЛАЗНЫЕ ЦВЕТА

**[СЕРЬЁЗНО] vivid-палитры — кислотные чистые цвета, выставленные пользователю штатно** (`index.css`):
```
:171  ocean vivid   --color-accent:#00c6ff  --accent-2:#0072ff
:179  sunset vivid  --color-accent:#ff416c  --accent-2:#ffb347
:187  lavender vivid --color-accent:#8360c3 --accent-2:#ff8fbf
:212  amber vivid   --color-accent:#ffd200  --accent-2:#ff8008
:221  berry vivid   --color-accent:#ff52a2  --accent-2:#9b36d9
```
- `#00c6ff` (неоновый циан), `#ff416c` (кислотный малиновый), `#ff52a2` (ярко-розовый), `#9b36d9` (чистый фиолетовый), `#ffd200` (чистый жёлтый) — это ровно те «вырвиглазные» значения из брифа.
- Градиент berry `#ff52a2 → #9b36d9` (`:221-222`) — розово-фиолетовая **вибрация** (комплементарно-близкие насыщенные тона на границе). Аналогично ocean `#00c6ff → #0072ff`.
- Эти акценты через `--color-accent-gradient` заливают ВСЕ `.btn`/`.btn-accent` (`index.css:566`) и попадают в тени `--shadow-accent` (`:317 accent 40%`) — т.е. кислота расходится по всему интерфейсу, не только на одной кнопке.

Да, это opt-in «насыщенный стиль», поэтому не КРИТИЧНО; но как дефолтно доступная тема это бьёт по общему визуальному качеству.

## Ось 7. НЕСОГЛАСОВАННОСТЬ СТИЛЕЙ

**[СЕРЬЁЗНО] Разнобой иконок: эмодзи vs SVG `Icon.jsx`.** Проект имеет компонент `components/Icon.jsx` (SVG), но одновременно в разметке живут эмодзи:
- `CareBanner.jsx:12` — `<span className="care-banner-icon">💛</span>`
- `HealthConsentGate.jsx:27` — `<div className="consent-icon">🔒</div>`
- `Watchlist.jsx:41` — рейтинговая звезда глифом `★`
- `food.badgeHave` (`en.json:567`) — `"✓ got it all"` (галочка-символ в строке).
Эмодзи рендерятся системным шрифтом/цветом эмодзи и не подчиняются палитре — рядом с монохромными SVG-иконами это визуальный разнобой.

**[НЕЗНАЧИТЕЛЬНО] Локальные переопределения вместо общих классов.** Есть хорошие общие `.btn/.btn-accent/.btn-ghost/.pill/.card` (`index.css:538-617`), но страницы заводят собственные кнопки/пилюли с иной геометрией: `Cycle.css:45` (`padding:9px 18px; color:#fff` — отдельная кнопка), `Work.css:518 .work-pill--debt`, `Study`-пилюли. Радиусы/паддинги кнопок местами расходятся с эталоном (`.btn padding:10px 18px` vs `Cycle 9px 18px`).

**[НЕЗНАЧИТЕЛЬНО] Смешение `px` и `rem`** для однотипных подписей между страницами (Legal/Footer/Settings в `px`, остальные в `rem`) — см. Ось 3.

## Ось 10. ЯЗЫК (развёрнуто)

### 10.1 Расхождение ключей — ЧИСТО
Автоматическое сравнение: **EN = 1078 ключей, UK = 1078 ключей**, разностей `EN∖UK` и `UK∖EN` — ноль. По набору ключей претензий нет (это сильная сторона).

### 10.2 [КРИТИЧНО] Непереведённые названия палитр в `uk.json`
3 из 7 названий палитр в украинском файле оставлены по-английски:
```
settings.palette.ocean    -> "Ocean Breeze"
settings.palette.sunset   -> "Sunset Vibes"
settings.palette.lavender -> "Lavender Sky"
```
при том что остальные 4 — переведены (`settings.palette.orange/green/amber/berry` на украинском). То есть в одном выпадающем списке «Палитра» в украинском интерфейсе одновременно английские и украинские подписи — грубый разнобой языка. (Проверено скриптом сравнения значений `uk==en` с латиницей.)

### 10.3 [СЕРЬЁЗНО] Юридический текст захардкожен в JSX
`Legal.jsx:17-70` — вся Политика конфиденциальности и Условия/оферта вшиты прямо в компонент двуязычным объектом (`CONTENT[doc][lang]`), а не в i18n. Это сделано осознанно (комментарий `Legal.jsx:7-8`: «цілісні документи»), документ всё же двуязычный, поэтому пользователь увидит верный язык. Но: (а) это обход единой i18n-системы; (б) бренд «Всетута» (кириллица) вшит и в английские строки (`Legal.jsx:33,63,65,70`), и в англ. `en.json:664 legal.footerNote: "Всетута — an educational diploma project."` — кириллица в EN-файле.

### 10.4 [НЕЗНАЧИТЕЛЬНО] Двуязычные тернарные строки вне i18n
`AuthControls.jsx:31,33` (`language==='uk'?'EN':'УК'`), `Legal.jsx:107,108,118,136` (`lang==='uk'?'Змінити тему':'Toggle theme'` и т.п.) — текст не через `t()`, а через ручной тернар. Отображается на правильном языке, но это дублирование механизма перевода и источник будущего рассинхрона.

### 10.5 Проверка — ЧИСТО
Grep по `placeholder|aria-label|title|alt` с кириллицей в JSX: **совпадений нет** (кроме двуязычных тернаров выше). Весь видимый UI-текст на страницах модулей идёт через `t()`. Кириллица в `.jsx` — почти исключительно комментарии (не считаются) и бренд «Всетута».

## Итоговый приговор

Интерфейс **в основе дисциплинирован**: единая система токенов, совпадающие наборы i18n-ключей, осознанная проработка `--color-on-accent` под vivid/pastel, локализованный горизонтальный скролл таблиц через `.table-scroll`, непротиворечивые z-index-слои. Голословно «разрушить» его нельзя — и честный прокурор это фиксирует.

Однако обвинение стоит на четырёх твёрдых опорах:
1. **Язык даёт течь в витрине настроек** — 3 из 7 палитр не переведены (КРИТИЧНО, видно каждому украиноязычному пользователю в первом же экране «Внешний вид»).
2. **Дисциплина токенов нарушается массово** — Work/Study/Cycle/Finance статусы и доменные палитры захардкожены hex-ом, причём текстовые цвета не переопределены для тёмной темы (КРИТИЧНО для консистентности тем).
3. **`color:#243` на пользовательском цвете смены** — конкретный путь к нечитаемому тексту (КРИТИЧНО, функциональный баг доступности).
4. **Кислотные vivid-палитры** и **разнобой эмодзи/SVG** — системный удар по визуальному качеству (СЕРЬЁЗНО).

Плюс хвост из мелочи: отсутствие `@media` в ~15 файлах, px-шрифты 10px в календаре смен, фикс-ширины колонок, слабые рамки на бледных палитрах.

**Вердикт: интерфейс добротный по архитектуре, но «грязный» по исполнению деталей.** Для дипломной защиты критичны прежде всего пункты 1–3 (их увидит/проверит комиссия в пять кликов), затем — чистка захардкоженных цветов и приведение иконографики к единому виду.
