## 2026-11-07 (сесія 2) — Ремедіація безпеки, фаза P2 (продовження): P2-5, P2-3

**Контекст:** той самий цикл — `adversarial-review/ПЛАН-ВИПРАВЛЕНЬ.md` згори вниз, кожен фікс має перевести відповідний PoC з CONFIRMED у REFUTED (перевірка наживо на `http://localhost:5080`).

**Зроблено цієї сесії:**
- **P2-5 — Фінанси: allowlist, DoS, вікно дати.** У `FinanceService.cs`:
  - allowlist із 33 ключів категорій (дзеркало `client/src/utils/financeCategories.js`) — `NormalizeCategory()` у Add/Update; невідомий ключ → 400 `invalid_category`; порожній → null (дозволено). Той самий allowlist на ендпойнті приховування категорії (`SetCategoryHiddenAsync`).
  - `GetStatsAsync`: рік поза `2000…поточний+1` → 400 `invalid_year` (було `new DateTime(year,…)` → `ArgumentOutOfRange` → **500** при `?year=0/-1/10000`).
  - `OccurredAt` обмежено вікном `2000-01-01 … now+1 доба` → 400 `invalid_date` (було: клієнт міг бек-/ф'ючер-дейтити історію, напр. 1900/2099).
  - ліміт (`SetLimitAsync`) тепер через `ClampMoney` — без від'ємних/абсурдних значень (баланс уже клампувався).
- **P2-3 — GET не мутує БД.** Прибрано лінивий INSERT-on-read у трьох місцях: `WorkService.GetSettingsAsync`, `StudyService.GetSettingsAsync`, `FinanceService.GetAsync`. Тепер дефолти віддаються з тимчасового об'єкта; рядок створюється лише при збереженні (PUT). (`CycleController` закрито раніше в P1-6.)

**Перевірено (наживо):**
- `08-finance/01-stats-year-dos` → **REFUTED** (0/-1/10000/99999 → 400, контроль 2026 → 200).
- `08-finance/02-category-allowlist` → **REFUTED** (увесь junk → 400; після чистки застарілих рядків список «сиріт» порожній).
- `08-finance/05-occurredat-and-mass-assignment` → **REFUTED** (1900/2099 → 400 `invalid_date`; mass-assignment на update і далі закрито). PoC оновлено під виправлену поведінку.
- `08-finance/07` → junk-hide **REFUTED**; `08-finance/08` → від'ємний ліміт **REFUTED**.
- P2-3: новий акаунт лише з GET `work|study`/settings і `finance` → **0 рядків** у `WorkSettings/StudySettings/FinanceAccounts`; після PUT — 1 рядок, значення коректно зберігаються (round-trip). `10-work/07` оновлено на реальну перевірку БД → GET-частина **REFUTED**.
- Валідний потік фінансів (income/expense/limit/balance/stats) → усе 200. Збірка сервера 0/0. Бекенд зупинено в кінці (0 слухачів на :5080).

**Відмічено в DoD:** P2-3, P2-5.

**Де зупинився / далі:** лишилось у P2 — **P2-6** (auth: rate-limit, lockout, антиенумерація нейтральними відповідями, gmail-alias нормалізація, bcrypt 72-байтна межа), **P2-7** (TOCTOU лічильника Quick Add — атомарний `UPDATE … WHERE used < limit`), **P2-8** (watchlist: сирота `ReturnTaskId` при видаленні книги + гонка `/schedule` + минулі дедлайни), **P2-9** (spam plan-trip ідемпотентність + автокатегоризація; сюди ж дедуп Food→список покупок), **P2-10** (інваріанти роботи/навчання: стелі розкладу/доходу/оцінок, напр. leave `end<start` мовчки свопиться — видно в `10-work/07`). Далі фаза P3.

**Побічні (не P2-5, свідомо лишені):** клампінг сум і банкове округлення (дизайн-рішення); регістрозалежний контракт `type` (`"income"` відхиляється) — нит, клієнт завжди шле правильний регістр; поповнення схованої категорії мовчки її активує — задокументована навмисна поведінка сервісу (будь-що внесене в історію = активне), не вразливість.

## 2026-11-07 — Ремедіація безпеки, фаза P2 (почато)

**Контекст:** виконуємо `adversarial-review/ПЛАН-ВИПРАВЛЕНЬ.md` згори вниз; кожне виправлення має переводити відповідний PoC з CONFIRMED у REFUTED (перевірка наживо на `http://localhost:5080`, PoC — `node adversarial-review/poc/<вкладка>/*.mjs`).

**Статус плану:** P0 (усі) та P1 (P1-1…P1-10) — закрито раніше. Цієї сесії зроблено P2-1, P2-2, P2-4.

**Зроблено цієї сесії:**
- **P2-1 — відкликання токена + коротший TTL.** Додано `User.TokenVersion` (міграція `AddTokenVersion`, застосована); claim `tver` у токені; `OnTokenValidated` у `Program.cs` звіряє версію з БД → старий/відкликаний токен = 401; `POST /api/auth/logout` інкрементує версію, клієнт кличе його на «Вийти»; TTL 90→7 днів. Видалений акаунт → 401 (заразом закрито orphan-FK 500).
- **P2-2 — ліміти довжини текстових полів.** `TextLimits` у `server/Authorization/Limits.cs`; `[StringLength]` на вільнотекстових полях DTO у 13 контролерах → 400 на перевищенні. Увага: на позиційних record-параметрах атрибут без `property:`.
- **P2-4 — CSS-ін'єкція через `color`.** Нотатки приймають лише hex (`#RGB`/`#RRGGBB`), інакше 400.
- **Бонус:** неіснуючий `productId` у списку покупок давав FK-500 → додано перевірку існування (системний/власний продукт) → 400 (і закрито IDOR на чужий продукт).

**Перевірено (REFUTED):** `14-system/03`, `13-settings/05`, `12-notes/02`, `03-calendar/06`, `09-study/05`, `07-health/condition-maxlen`, `12-notes/04`, `05-shopping/data-limits`, `08-finance/08`(desc), `04-watchlist/02`. Збірка сервера 0/0, клієнт збирається. Регресій валідних (коротких) потоків немає. Бекенд зупинено в кінці.
