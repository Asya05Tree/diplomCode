# План виконання лабораторних з МАПЗ

**Дисципліна:** Моделювання та аналіз програмного забезпечення
**Тема диплому:** Розробка планувальника завдань
**Реальна система:** ASP.NET Core Web API (C#) + Entity Framework Core + **MySQL**, фронтенд React + Vite, автентифікація JWT, двомовність uk/en. Модульна архітектура з компонентом правил `RuleEngine` («правила як дані»).

---

## Головний принцип розподілу роботи

Умовні позначки:
- 🟢 — **Claude робить повністю** (текст, таблиці, специфікації, готові файли діаграм)
- 🟡 — **Claude готує зміст, користувач переносить/доформатовує** (у GUI-редактор або звіт)
- 🔴 — **тільки користувач** (операції в GUI, скріншоти, захист)

### Про інструменти діаграм (важливо)

Завдання вимагають **StarUML** (ЛР3–9) і **Rational Rose** (ЛР8, діаграма впровадження).

**Чи можна замінити на draw.io (diagrams.net)?** Технічно — так: draw.io підтримує всі потрібні типи діаграм (use case, class, sequence, state, activity, component, package, deployment). Більше того, формат `.drawio` — це XML, і **Claude може згенерувати готові файли діаграм**, які потрібно лише відкрити в draw.io, за потреби підправити й експортувати в PNG для звіту.

⚠️ **Застереження:** це формальна вимога кафедри. Перед заміною **узгодь із викладачкою (Бондаренко С.В.)**, чи приймаються діаграми з draw.io замість StarUML/Rational Rose. Якщо так — Claude генерує `.drawio` файли (рівень 🟢/🟡). Якщо ні — Claude готує повні текстові специфікації, користувач малює у StarUML (рівень 🟡).

## ЛР1 — Аналіз предметної галузі (звіт Word)

| Частина | Хто | Деталі |
|---|---|---|
| Таблиця аналогів (3+): назва, виробник, архітектура, мова, 5+ функцій, переваги, недоліки, джерело | 🟢 | Аналоги-планувальники: Todoist, TickTick, Notion |
| Основні задачі (5+) | 🟢 | З реального коду/спеки |
| Користувачі (2–3) | 🟢 | Гість / Базовий / Преміум |
| Схема структури | 🟢 | Claude генерує `.drawio` шарової архітектури |
| Сценарії (3+) | 🟢 | Реальні флоу |
| Таблиці БД (5+) | 🟢 | Реальні поля з `AppDbContext` і моделей |
| Апаратні/програмні засоби | 🟢 | ASP.NET Core, EF Core, MySQL, React/Vite, JWT |
| Вихідні дані (3+) | 🟡 | Claude описує, скріншоти робить користувач |
| Висновки, оформлення ДСТУ | 🟡 | Claude — чернетку, користувач — фінал |

**Статус:** виконується зараз. Старий звіт у `1/` описував іншу (ширшу) версію системи — переробляється під нинішню.

## ЛР3 — Use Case Diagram

Вимоги: усі актори, по 3 UC на актора, усі 4 типи зв'язків (association, generalization, extend, include).

- Актори: Гість → Базовий → Преміум (**generalization** між рівнями), Адміністратор довідників.
- include: «Сформувати меню» → «Перевірити запаси». extend: «Відмітити покупку» → «Списати кошти».
