## 1. Методологія

Парсер — детермінований, на правилах, без зовнішніх сервісів. Тому замість «на око» я
**виконав реальний парсер** (`parseInput`) на фіксованій даті `NOW = 2026-11-07 09:00`
(субота, ISO-день 6) проти **200+ сценаріїв** у 23 розмічених наборах + точкові проби
(кількості, кілька дат, гроші, заперечення, фаззі-словник, російська мова).

Для кожного кейсу зафіксовано: вхід, очікувану кількість задач, очікуваний розподіл
дат/часу, фактичний вихід парсера, фактичний розподіл, втрачені/хибні задачі.
Враховано **фронтовий гейт мови**: якщо `findUnsupportedChars(text)` не порожній, UI
**нічого не парсить** — тому для таких входів фактична кількість створених задач = 0.

Гармонізація метрик (на рівні **сегментації задач**):
- **TP** = `min(очікувано, фактично)` на кейс (збіг кількості виділених задач);
- **Recall** = ΣTP / Σочікувано; **Precision** = ΣTP / Σфактично;
- **% втрачених** = Σ`max(0, очікувано − фактично)` / Σочікувано.
- Коректність **вмісту** (дати/час/модуль/запаси) перевірялась окремо, пополе.

> Увага: сегментаційні P/R НЕ бачать змісту. Задача може «зматчитись» за кількістю, але
> мати зіпсовану назву чи неправильну дату — це ловить окрема пополева перевірка
> (див. `quick-add-failures.md`).

Артефакти прогону: `harness.mjs`, `results.json`, `probe*.mjs` (у scratchpad сесії).

## 3. Головні висновки (класами)

1. **CRITICAL — `the`/`them`/`they` → `then`.** Фаззі-шар «виправляє» найчастіше
   англійське слово `the` на роздільник `then`, і одна задача дробиться на дві.
   Ламає більшість англійських фраз виду «verb the noun». (QA-01)
2. **CRITICAL — безкомові багатозадачні рядки злипаються.** Приклад із ТЗ
   (укр. варіант, 7 намірів) дав **2 задачі, 5 втрачено (71%)**; дати/час причепились
   до «блобів». (QA-02)
3. **CRITICAL — приклад із ТЗ дослівно = 0 задач.** Через одну російську літеру «ы»
   («цветы») весь рядок блокується гейтом; користувач бачить лише дрібну примітку і
   жодної задачі — тиха повна втрата. (QA-03)
4. **HIGH — російська (спільні літери) парситься як українська.** «позвонить маме»,
   «сделать уроки» проходять гейт і стають сміттєвими задачами без попередження. (QA-04)
5. **HIGH — фаззі псує реальні слова.** «квіти»→«квітня» (квіти→місяць квітень). (QA-05)
6. **HIGH — кількості гинуть.** «купити 2 кг цукру» → назва «купити кг цукру» + безглуздий
   вибір дати/часу для «2». (QA-06)
7. **HIGH — модуль косметичний; інтеграцій майже немає.** Створюються лише: загальна
   задача (+ колір-тег), предмет Навчання, запас Їжі. Фінанси/нотатки/список покупок/
   медіа/робота/здоров'я/рецепти/контакти/проєкти — **НЕ створюються**. (QA-07, див.
   `integration-gaps.md`)

Повний перелік — у `quick-add-failures.md`, `edge-cases.md`, `integration-gaps.md`.
Покрокові відтворення — у `reproducible-bugs.md`.

## 5. Що працює добре (щоб не «виправити» зайвого)

- Коми, `;`, `.`, `!`, `?`, фрази-роздільники («потім», «then») — дроблять коректно.
- Дієслівний поділ без об'єкта НЕ дробить («сходити купити хліб» = 1 задача).
- Тривалість vs дата («4.5 години» = 270 хв, не 4 травня) — коректно.
- Невалідні час/дата («99:99», «32.13», «о 25») — відкидаються/дають вибір, не падають.
- Відносні дати, дні тижня, місяці, дедлайни з числом, успадкування дати через кому —
  працюють на базових формах.
- Запаси Їжі та предмети Навчання — єдині реально інтегровані сутності, працюють.
