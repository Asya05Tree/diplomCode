# Quick Add — Інтеграційні прогалини з рештою системи

**QA-07 · HIGH.** Головний факт: у `QuickAdd.jsx` функція `createAll` викликає лише три
операції створення:

```
import { createTask }      from '../../api/tasks'   // загальна задача (+ moduleCode-тег)
import { addSubject }      from '../../api/study'   // предмет Навчання (умовно)
import { addStockByName }  from '../../api/food'    // запас Їжі
```

Тобто з усіх модулів системи **Швидке додавання інтегроване лише з двома сутностями**
(предмет Навчання, запас Їжі). Решта «модулів» — це **косметичний тег кольору** на
звичайній задачі-`TaskItem`.

Підтвердження на бекенді: `TasksController.CreateTaskRequest` приймає `ModuleCode`, який
валідовано проти allowlist і зберігається як рядок-тег на `TaskItem`. Жодної маршрутизації
в інші таблиці немає.

---

## Матриця інтеграції (намір → що очікує користувач → що реально стається)

| Намір у тексті | Модуль (тег) | Очікувана сутність | Реально створюється | Статус |
|---|---|---|---|---|
| `купити молоко` | shopping | пункт у **Списку покупок** | задача з тегом shopping | ❌ не інтегровано |
| `подивитися фільм` / `почитати книгу` | media | запис у **Медіа/Перегляд** | задача з тегом media | ❌ |
| `приготувати борщ` | food | зв'язок із **Рецептом/стравою** | задача з тегом food | ❌ (рецепти — ні) |
| `в мене є молоко` / `додати до запасів` | food | **StockItem** (запас) | StockItem | ✅ працює |
| `заплатити 500 грн` | finance | **витрата** з сумою | задача з тегом finance | ❌ (сума в назві) |
| `отримав зарплату 20000` | finance | **дохід** | задача (або нічого) | ❌ |
| `записати нотатку: …` | notes | запис у **Нотатках** | задача з тегом notes | ❌ |
| `нарада з клієнтом` | work | зустріч/контакт у **Роботі** | задача з тегом work | ❌ |
| `співбесіда`, `відрядження` | work | подія процесу Роботи | задача з тегом work | ❌ |
| `пара математики` | study | елемент розкладу/дедлайн Навчання | задача (+ предмет, якщо новий) | ⚠️ частково |
| новий предмет у фразі про пару | study | **Subject** у Навчанні | addSubject (чекбокс) | ✅ умовно |
| `прийняти таблетки` / `вітаміни` | health | запис **Аптечки**/візиту | задача з тегом health | ❌ |
| `записатися до лікаря` | health | **візит/чекап** | задача з тегом health | ❌ |
| будь-який намір | — | **контакт** (client.js) | — | ❌ (контакти недосяжні) |
| будь-який намір | — | **проєкт** (work process) | — | ❌ |
| будь-який намір | — | **категорія** витрати/справи | — | ❌ (категорій немає) |
| менструальний цикл | — | запис **Cycle** | — | ❌ недосяжно |

Легенда: ✅ працює · ⚠️ частково · ❌ прогалина.

## Деталізація прогалин

### QA-07a — Список покупок
`shopping.js` має власний API списку покупок, але Quick Add його не викликає. «купити X»
не з'являється у Списку покупок (а користувач майже напевно цього очікує, бо модуль
називається «Покупки»). Втрачається весь міст між швидким додаванням і реальним списком.

### QA-07b — Фінанси (витрати/доходи/суми) — див. також QA-10
Немає захоплення **суми**, **валюти**, **напрямку** (витрата/дохід), **категорії**.
`finance.js` API не викликається. «заплатити 500 грн» → звичайна задача; баланс/статистика
Фінансів не змінюються. Для планувальника з єдиним балансом (planner-spec §3.6) це
істотна прогалина.

### QA-07c — Нотатки
`notes.js` не викликається. «записати нотатку …» створює **задачу в календарі**, а не
нотатку в розділі Нотатки. Текст нотатки (суть) опиняється в назві задачі.

### QA-07d — Рецепти/страви
Інтегровано лише **запаси** (інгредієнти). «приготувати борщ» не прив'язується до рецепта,
не додає інгредієнтів у список покупок, не створює страву. Односторонній місток (лише
stock-by-name).

### QA-07e — Робота: контакти, зустрічі, проєкти, процес
`work.js` (контакти/зустрічі/процес-канбан/розклад змін) не викликається. «нарада з
клієнтом», «співбесіда», імена людей — усе стає тегованою задачею; контакт/зустріч/проєкт
не створюються. Імена людей ніде не витягуються (окрім викладача в Навчанні).

### QA-07f — Здоров'я / Аптечка / Чекапи
`medicineCabinet.js`, `checkup.js`, `healthProfile.js` не викликаються. «прийняти
таблетки», «вітаміни», «записатися до лікаря» → теговані задачі, без записів аптечки чи
візитів.

### QA-07g — Категорії
У системі немає концепції «категорія» у Quick Add: ні для витрат, ні для справ. Згадана в
ТЗ інтеграція з категоріями **відсутня повністю**.

### QA-07h — Контакти та імена людей
Єдине місце, де витягується ім'я людини — **викладач** у Навчанні (`extractStudy`). У
решті випадків імена («подзвонити Іванові», «зустріч з Олею») лишаються в назві й не
зв'язуються з жодним контактом.

## Наслідок для оцінки якості

Класифікація модуля в Quick Add створює **ілюзію інтеграції**: користувач бачить, що
задачу віднесено до «Фінанси»/«Покупки»/«Нотатки», і розумно очікує, що вона з'явиться
у відповідному розділі. Фактично вона лишається звичайною календарною задачею з
кольоровим тегом. Це систематичне джерело «загублених» (з точки зору користувача) даних,
навіть коли парсер спрацював правильно.
