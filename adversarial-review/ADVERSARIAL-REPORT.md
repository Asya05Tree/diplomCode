# Adversarial review — «Всетут» (зведений звіт)

**Дата:** 2026-11-07 · **Метод:** 14 суб-агентів, по одному на вкладку з `adversarial-перевірки/`, пройшлися по **кожному** пункту чеклистів і намагалися **довести, що проєкт ламається**. Кожну підтверджену атаку **відтворено тестом** проти **живого бекенду** (`http://localhost:5080`, ASP.NET Development + MySQL у Docker). **Жоден файл вихідного коду не змінювався** — агенти працювали в режимі read-only і писали лише в `adversarial-review/`.

> Відтворюваність: усі PoC — це запускні `node *.mjs` скрипти в `adversarial-review/poc/<вкладка>/`. Спільний хелпер `poc/_lib/provision.mjs` створює реальні акаунти через справжній email-code флоу (код читається з MySQL, бо SMTP вимкнено) і вміє **підробляти JWT** закомміченим ключем. Приклад запуску — див. останній розділ.

---

## Головний висновок

Проєкт **ламається системно**, а не точково. Три кореневі причини породжують більшість критичних знахідок:

1. **Автентифікація тримається на закомміченому плейсхолдер-ключі.** `Jwt:Key = "CHANGE_ME_TO_A_LONG_RANDOM_SECRET_IN_PRODUCTION"` (`server/appsettings.json:12`) лежить у git. Будь-хто підробляє токен для **будь-якого** `userId` без пароля → повне перевтілення в будь-який акаунт. Сама крипто-перевірка підпису/терміну коректна (alg:none / чужий ключ / прострочений → 401) — діра саме в **ключі**, а не в алгоритмі. Це знецінює кожну перевірку власності нижче.
2. **Умовні модулі (Навчання / Робота / Цикл) не гейтяться на сервері.** Приховування вкладок — лише клієнтське. Акаунт з `studentType:'none'`, `isWorking:false`, `gender:'male'` вільно робить повний CRUD на `/api/study`, `/api/work`, `/api/cycle` (усе 200, дані зберігаються).
3. **Немає валідації вхідних даних → некеровані 500 (self-DoS) + відсутні ліміти довжини.** Десятки ендпойнтів падають у `500` з повним stack trace (DeveloperExceptionPage увімкнено) на граничних/кривих даних, а відсутність серверних лімітів довжини дозволяє зберігати 8 КБ–200 КБ сміття.

Додатково наскрізне: **платний пейвол Quick Add обходиться** (mock-режим у проді + анонімний callback без перевірки підпису), **токен не відкликається** (90 днів, logout лише клієнтський), **секрети в git** (JWT, WayForPay, пароль БД), і кілька **GET-ендпойнтів мутують дані** (неідемпотентні).

## Що НЕ зламалося (чесні спростування)

Щоб звіт був збалансований, агенти явно перевіряли і **спростували** низку гіпотез чеклистів:

- **Per-record IDOR здебільшого закритий.** Фінанси, Календар, Перегляд, Нотатки, Налаштування, Цикл, Робота, Здоров'я: усі крос-юзерні GET/PUT/DELETE повертають 404, дані не чіпаються, запити скоуповані за `UserId`. (Винятки, де IDOR **підтверджено**: Їжа — запаси/рецепти; Навчання — читання чужого предмета через assignment.)
- **Stored-XSS у тексті інертний** скрізь: React екранує текстові вузли, `dangerouslySetInnerHTML` не використовується. (Виняток: CSS-ін'єкція через `color` у Нотатках — інший sink, `style=`.)
- **Mass-assignment привілейованих полів** переважно закритий DTO-обмеженням (`UserId/Id/Status` не біндяться). (Винятки: профіль у Здоров'ї/Налаштуваннях — `StudentType/IsWorking`; дрібні мертві поля в Роботі.)
- **Крипто-перевірка JWT коректна** (alg:none/чужий ключ/прострочений → 401); проблема лише в закомміченому ключі.
- **i18n-паритет uk/en** на перевірених модулях повний (auth 0 розбіжностей, study 113=113, food 56/56, quick-add 91/91).
- Грошові обчислення — `decimal(18,2)` без float; клампи сум працюють; ділення на нуль у статистиці/прогнозах захищене.

## Як запускати PoC

```bash
# Бекенд має бути запущений на http://localhost:5080, MySQL (docker planner-mysql) — піднятий.
cd adversarial-review/poc

# один тест:
node 03-calendar/01-duplicate-exception-500.mjs
node 14-system/01-*.mjs
node 08-finance/01-stats-year-dos.mjs

# усі тести однієї вкладки:
for f in 11-cycle/*.mjs; do echo "== $f =="; node "$f"; done
```

Кожен скрипт друкує `CONFIRMED`/`REFUTED` з рядком «очікувано vs спостережено» і, де доречно, вставленим HTTP/DB-виводом. Скрипти створюють **реальні** акаунти в dev-БД з email-ами `adv.t<NN>.*@gmail.com` і не виконують деструктивних глобальних операцій.

> **Увага (сліди в dev-БД):** живе відтворення залишило тестові акаунти `adv.t*@gmail.com` та підняло кільком з них `QuickAddUnlocked=1` — це очікувано для репро і стосується лише dev-бази `planner`.
