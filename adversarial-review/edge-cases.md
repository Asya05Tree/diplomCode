# Quick Add — Межові випадки (edge cases)

Поведінка на шумі, сміттєвому вводі, пунктуації, невалідних значеннях і на нововведеному
обмеженні довжини. Для кожного — пріоритет, вхід, очікування, факт.

---

## Шум / безглуздий текст

| Вхід | Очікувано | Фактично | Оцінка |
|---|---|---|---|
| `абоба` | задача з сирою назвою | «абоба», confidence=low, ✔ увімкнена | OK (за дизайном) |
| `asdkfj` | те саме | «asdkfj», low, **✔ увімкнена за замовч.** | див. QA-16 |
| `ееее` / `хочу` | відкинути | відкинуто (filler-only) | OK |
| `в на до` | відкинути | відкинуто (edge-only) | OK |
| `ну короче ееее хм` | відкинути | відкинуто | OK |
| `the a an to` | відкинути | відкинуто (edge-only EN) | OK |
| `!!!???` / `...` | нічого | нічого | OK |
| `12345` | 1 задача-назва | «12345» (5-значне не ловиться як дата/число) | OK |

**QA-16 · LOW ·** Сміттєві low-задачі (`asdkfj`, зіпсована російська) приходять у модалку
з **увімкненим чекбоксом** (`include = Boolean(title)`), тож один клік «Створити» легко
створює випадкове сміття. Для low-confidence варто було б знімати відмітку за замовчуванням.

## Пунктуація

| Вхід | Очікувано | Фактично | Оцінка |
|---|---|---|---|
| `купити молоко. помити посуд.` | 2 (тверді межі) | 2 | OK |
| `купити молоко; помити посуд` | 2 | 2 | OK |
| `купити молоко! помити посуд?` | 2 | 2 | OK |
| `купити молоко,помити посуд` | 2 (кома без пробілу) | 2 | OK |
| `купити   молоко` | 1 (зайві пробіли) | 1 | OK |
| `КУПИТИ МОЛОКО` | 1 (верхній регістр) | 1 | OK |
| `buy milk...then wash dishes` | 2 | 2 | OK |

Пунктуаційний розбір стійкий. Крапка всередині `4.5`/`15.11` не ламає (за дизайном).

## Невалідні дата/час (мають відхилятись, не падати)

| Вхід | Фактично | Оцінка |
|---|---|---|
| `зустріч о 99:99` | час відкинуто (хв>59), amb=0, задача «зустріч» | OK |
| `подія 32.13` | не дата (день>31, міс>12); «32» → ambiguous? → так, лишається вибір | прийнятно |
| `подзвонити о 25` | година>23 → час відкинуто, «25» → ambiguous-вибір | прийнятно |
| `meeting at 25` | те саме | прийнятно |
| `зустріч 00:00` | time=00:00 | гранично (північ як валідний час) |
| `0` | порожня назва + вибір 00:00 | див. QA-17 |

Падінь/винятків не виявлено. Невалідні значення або відкидаються, або переходять у
ambiguous-вибір — без краху.

## Довжина вводу (нове обмеження `maxLength = 300`)

**QA-11 · MEDIUM ·** Поле `quick-add-input` отримало `maxLength={300}` (додано в цій сесії).
Наслідок: вставлення довгого списку справ (понад 300 символів) **тихо обрізається**
браузером — хвіст тексту (а отже й задачі в ньому) **втрачається без попередження**.
Лічильник «N/300» показує межу, але при *вставленні* обрізання не очевидне.

- **Очікувано:** або більший ліміт, або попередження/заборона вставити довше, або
  багаторядкове поле.
- **Фактично:** мовчазне відсікання на 300 символах.

Також: поле — `<input type="text">` (однорядкове); Enter одразу запускає розбір, тож
багаторядкове введення/вставлення з переносами незручне.

## Багатозадачність без ком (ключовий клас — див. QA-02)

| Вхід | Задач | Нотатка |
|---|---|---|
| `сходити купити хліб` | 1 | об'єкта між дієсловами нема → НЕ дроблять (правильно) |
| `go buy bread` | 1 | «go» не в списку дієслів → не дробить |
| `подивитись кіно почитаю книгу` | 2 | є об'єкт → дробить (правильно) |
| `піти … полити … подумати … (без ком)` | **2 з 7** | повсякденні дієслова не в списку → злипання (**QA-02**) |

Висновок: якість багатозадачного розбору **критично залежить від того, чи поставив
користувач коми/роздільники**. Без них — велика втрата.

## Мовні межові випадки

| Вхід | Фактично | ID |
|---|---|---|
| `勉強する` (японська) | blocked (гейт), 0 задач | OK (очікувано) |
| `полить цветы завтра` (рос., є «ы») | blocked, 0 задач | частково QA-03 |
| `позвонить маме` (рос., лише спільні літери) | НЕ blocked → сміттєва задача | **QA-04** |
| `купити milk завтра` (uk+en) | 1 задача, date завтра, lang=mixed | OK |
| `meeting у понеділок` (en+uk) | 1 задача, date понеділок | OK |

Підтримуваний змішаний uk+en працює добре; проблема саме з російською на спільних
літерах (QA-04) та з повним блоком через один чужий символ (QA-03).

## UX модалки підтвердження (вкладки, додані в цій сесії)

**QA-18 · LOW ·**
- Зміна «Модуль» у рядку **автоматично перемикає активну вкладку** на новий модуль —
  рядок «стрибає» з-під очей користувача (може дезорієнтувати при масовому редагуванні).
- Запаси винесено в окрему вкладку; якщо користувач не відкриє її перед «Створити»,
  він може не побачити, що там є позначені продукти (хоча вони все одно створяться).
- Корекції фаззі показуються над вкладками — але поділ (`the→then`) уже стався, і
  користувач бачить зайву задачу як доконаний факт.

Ці пункти — не втрата даних, а ризики непорозуміння.
