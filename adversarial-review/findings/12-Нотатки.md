## 8. Безпека (XSS / color)

- **[I/Positive] ⚪ Stored XSS via note text does NOT execute.** Evidence: render sinks are `Notes.jsx:78-85` `<textarea value={note.text}>` and `Notes.jsx:99` `{note.text.length}` (number). No `dangerouslySetInnerHTML`/`innerHTML` in `Notes.jsx` or `Board.jsx`. Reproduction: `poc/12-notes/03-xss-text.mjs`:
  ```
  stored verbatim on server: true
  stored value: "<img src=x onerror=alert(document.cookie)><script>alert(1)</script>"
  REFUTED (script-XSS) ⚪ — no innerHTML sink
  ```
  Impact: safe today. **Caveat:** server stores raw HTML verbatim (no sanitization, `NotesController.cs:47,62`); any future markdown/`innerHTML` render instantly becomes stored XSS. Recommend a regression test.
- **[H] 🟠 Color = CSS-injection / external-resource vector.** Evidence: sink `Notes.jsx:77` `style={{ background: note.color }}` with server value; server accepts arbitrary string (§6-B). React blocks breaking out of the inline-style object and JS execution, **but** accepts valid CSS `background` values incl. `url(https://evil.example/...)`, `image-set(...)`, gradients. Reproduction: `poc/12-notes/02-color-injection.mjs` stored `red; background: url(https://evil.example/beacon.gif)` verbatim (output in §6-B). Impact: when victim opens Notes, browser fetches the external URL → tracking beacon / IP deanonymization / CSP bypass if no CSP. Fix: whitelist the 6 HEX colors on client **and** server.
- **[M] 🟡 No server palette check ⇒ GET reflects dirty colors.** Evidence: `Get` returns stored `Color` as-is (`NotesController.cs:37`). Reproduction: PoC02 (reflected verbatim). Impact: validation must be on input.
- **[L] 🔵 Board `localStorage` → `new Image(); img.src = saved`.** Evidence: `Board.jsx:38-43`. Value is attacker-of-self only; no cross-user XSS. See §10 corrupted-dataURL.
- **[I] 🔵 CSP not set ⇒ §8-H fully exploitable.** Not observed any CSP header on API/beacon path; recommend `Content-Security-Policy` with restricted `img-src`.
