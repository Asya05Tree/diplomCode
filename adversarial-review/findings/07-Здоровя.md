# Adversarial findings — TAB 07 «Здоров'я»

Area: medicine cabinet, chronic conditions, checkup visits, health profile. SENSITIVE medical data.
Live server: `http://localhost:5080`. DB: `planner-mysql` (1884 medicines, 514 substance interactions).
PoCs: `adversarial-review/poc/07-health/*.mjs` (each prints CONFIRMED/REFUTED with observed-vs-expected).

Legend: 🔴 critical · 🟠 major · 🟡 moderate · 🔵 minor/UX · ⚪ REFUTED · 🟢 verified-good.

> Scope of live testing: backend authz/validation/perf/privacy were reproduced against the running API + DB.
> Pure-frontend items (§1–§5 rendering/a11y/CSS) are verdicted by source review (file:line), since no browser-driver is in scope; they are not refuted, just not live-reproduced.

  No `[MaxLength]`/column-length config on `UserCondition.NameUk`, `HealthVisit.Place/Note/DoctorKey`, `Tag.Key/DisplayName`. Client `MAX_LEN` (name=60, description=200) is UX only. Direct API writes arbitrary-length strings → DB bloat, UTF-8 truncation at driver level, DoS.
- **10.4** 🟡🟢 Live: `profile-clamp-range.mjs` — server `Math.Clamp` duplicates client `RANGES` (weight 1..500, height 30..300, age 1..120). Good double protection. (Silent — see §3.1.)
- **10.5** `MedicineService.DetectScript:128-139` returns `uk`/`en`/null; a mixed uk+lat query (e.g. "Корвалол L") → null → empty results with no explanation (`SearchAsync:60`). Latin-brand names may be unfindable by a Cyrillic query. Digits/apostrophes ignored.
- **10.6** `validation.js:24-33 filterWords` keeps `[A-Za-zА-ЯҐЄІЇа-яґєіїʼ' -]`, truncates to 40 → "Омега-3" loses "3". Non-obvious restriction for allergen names.
