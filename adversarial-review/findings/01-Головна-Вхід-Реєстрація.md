| 8.2 | **No rate limiting → code brute force + multiple live codes** | 🔴 CRITICAL — `code-bruteforce.mjs`: no `AddRateLimiter` anywhere (`Program.cs`). ## Confirmed issues, by severity

**🔴 CRITICAL**
1. **JWT forgery via committed placeholder key** (`appsettings.json:12`) — forge a token for any userId, no password; `/me=200`. `jwt-forgery.mjs`. (§7.3)
2. **No rate limiting → 6-digit code brute force** (~102 guesses/s, no lockout, wrong guesses don't consume the code, 5 codes valid at once). `code-bruteforce.mjs`. (§8.2)

**🟠 HIGH**
3. **90-day, no-jti, non-revocable token; logout is client-only** — reused after logout → 200. `token-lifetime-revocation.mjs`. (§7.2)
4. **Account enumeration via `send-code`** — `email_taken` (400) vs 200. `enumeration.mjs`. (§8.1)
5. **500s leak full stack traces** (file paths, EF/SMTP internals, request headers) on malformed/oversized email, non-numeric sub, unique-race. `server-validation.mjs`, `sub-nonnumeric-500.mjs`. (§6.x/§8.6)
6. **No server email-format validation** → malformed `@gmail.com` reaches EmailService → unhandled 500. `server-validation.mjs`. (§6.3)
7. **No anti-automation on login/send-code** — unlimited password attempts + email bombing + unbounded table growth. (§8.2b/§8.10)

**🟡 MEDIUM**
9. bcrypt 72-**byte** truncation vs 72-**char** limit — different Cyrillic passwords sharing 72-byte prefix log in. `bcrypt-truncation.mjs`. (§9.5)
10. Gmail alias/dot bypass → 3/3 multi-accounts, defeats `email_taken` + free quota. `gmail-alias.mjs`. (§9.2)
11. Gender stored verbatim, no whitelist (incl. `<script>`). `server-validation.mjs`. (§6.4)
12. No `UseHttpsRedirection` — cleartext token/password. (§6.10)
13. Non-numeric `sub` → 500 (`int.Parse`). `sub-nonnumeric-500.mjs`. (§7.5)
14. Token in localStorage (XSS-exfiltrable, pairs with 90-day token). (§7.1)
15. Non-crypto RNG (`Random.Shared`) for verification code. (§8.3)
16. Verification code stored plaintext + logged in dev. (§8.4)
17. Oversized email → 500 (no length guard, `varchar(255)`). (§6.5)
18. CodeInput: six unlabeled inputs / `auth-error` not `aria-live` (a11y). (§5.1/§5.8)

**🔵 LOW** — separator-only nickname valid; whitespace-only password; client/server password-truncation divergence; loose email regex (double-dot); no `color-scheme:dark`; FOUC on cold load; missing-i18n-key shows raw key; `missing_fields`/`invalid_credentials` unmapped; login always shows generic error (hides 500s); no code TTL cleanup; two-SaveChanges no transaction; code-reuse race (code-trace); idempotency; double-submit; no loading spinner; unique-email race → 500; CodeInput arrows/Delete unhandled; empty-nickname send-code; alt/label duplication.

**⚪ Notable REFUTED/OK** — `intervalDays=0` division (clamped to 1); `findMaximalCombos` perf (capped at 20); `a@@b..c` rejected; CORS wildcard (only dev origin reflected); login enumeration-safe; model-binding returns clean 400 (no NRE); open redirect (none); CSRF (header auth); i18n key parity (0 mismatches); alg:none/HS-RS confusion (symmetric only); `gmail.com.evil.com` rejected; reduced-motion & focus-visible handled.
