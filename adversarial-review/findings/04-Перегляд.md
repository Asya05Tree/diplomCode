## 1. Фронтенд — дворівневі вкладки, логіка

- 🔵 **1.1 Дворівнева структура / вкладка «Борги» лише для книг.** `statuses = kind === 'book' ? [...STATUSES, DEBT_STATUS] : STATUSES` — `Watchlist.jsx:261`. Correct by code.
- 🟡 **1.2 `switchKind` не скидає поповери (`sched`/`editId`/`reviewEditId`/`edits`).** `switchKind` (`Watchlist.jsx:90-96`) resets only `genreFilter/typeFilter/draft/status`. An open popover survives a kind switch. In practice the card is not rendered for the other kind (filtered out), so the popover does not display, and `submitSchedule`/`handleSaveEdit` act by the captured `item` id, not the page `kind` — so no cross-record write happens. UX wart (popover "pops back" on return), not a data bug. Confirmed by static read.
- 🔵 **1.3 Лічильники не подвоюють борг.** `counts.planned/in_progress` use `!it.isDebt`; `debt` uses `it.isDebt`; `visible` excludes `isDebt` from planned/in_progress (`Watchlist.jsx:262-281`). Verified server-side in PoC 09 (overdue library book appears only in Debts). OK.
- 🟡 **1.4 Скалярні стани поповерів — пріоритет `sched` над `editId`.** Render is `sched?.id===item.id ? … : editId===item.id && editForm ? …` (`Watchlist.jsx:513,546`). `openSchedule` does not clear `editId`; `startReview` does not clear `sched`. - 🔵 **1.5 «Завершити» з «У планах».** Button shown for any non-`done` (`Watchlist.jsx:655`). Deliberate: produces `done` with no `StartDate`/event. See §9 note about library books completed from planned still carrying an active return reminder — covered in 9.x.
- 🔵 **1.6 Форма додавання лише у `planned`; Add завжди `Status="planned"`.** `Watchlist.jsx:351`; server forces `Status="planned"` (`MediaController.cs:154`) and ignores client `status` (PoC 02 "status not mass-assignable on Add"). OK.
- 🔵 **1.7 Повторний клік по зірці → 0 → `rating||null` → null.** `onChange(n===value?0:n)` (`Watchlist.jsx:39`); `handleSaveDone` sends `rating||null` (`Watchlist.jsx:228`). Client clears correctly. But see 8.5 — the server API itself clamps 0→1.

## 11. Продуктивність і надійність

- 🔵 **11.1 Get без пагінації, клієнт рендерить усе.** All items loaded + filtered in memory each render (`Watchlist.jsx:260-281`); hundreds/thousands of animated cards will strain the DOM. Not stress-reproduced here; by-design risk.
- 🔵 **11.2 Кожна мутація = повний `reload()`.** `Watchlist.jsx:87` — full `GET /api/media` after every action; no optimistic update. Confirmed by read.
- 🔴 **11.3 Гонка `/schedule` — немає транзакції/локу.** PoC 05 (two runs): 6 parallel `/schedule` on one planned item → **all 6 return 200**, 6 calendar reading-events created, `item.TaskId` overwritten by the last → **5 orphaned events** every run. The `already_scheduled` guard is pure TOCTOU (read-check-create without locking).
  ```
  Parallel /schedule x6: statuses=[200,200,200,200,200,200]
  Calendar reading-events created for this item: 6
  item.TaskId now = 134
  Orphaned events (not referenced by item.TaskId): 5
  ```
- 🟡 **11.4 Гонки завершення/повернення.** Same lock-free pattern on `/status` and `/return`; concurrent `/schedule`+`/status done` or double `/return` can produce inconsistent `TaskId`/event state. Root cause shared with 11.3; not separately scripted.
- 🔵 **11.5 Гонка повернення на planned (перший видаляє, другий 404).** Expected per scoping; after `reload` the card disappears. Consistent with PoC 08 delete-nonexistent→404.
- 🟡 **11.6 Кнопки не стають `disabled` під час запиту.** No local `busy` state on Delete/Finish/Return (`Watchlist.jsx` actions) → double-click fires duplicate requests. Idempotency softens it (2nd Delete→404, 2nd `/status done`→400) but 11.3 shows double-click on Schedule is actively harmful. Confirmed by read.
- 🔵 **11.7 Серія синхронізації з календарем.** With the 9.9 orphan + 11.3 race, `TaskId`/`ReturnTaskId` can point to deleted or duplicate events. Covered by those findings.
- 🔵 **11.8 `Add` робить два `SaveChangesAsync`, не в транзакції.** `MediaController.cs:160-162` — if `SyncReturnTaskAsync` throws, the media row persists without its reminder. Partial-failure window; not reproduced.
- 🔵 **11.9 `useEffect` guard `cancelled`.** Present (`Watchlist.jsx:68-85`) — no setState after unmount. OK.
- 🟡 **11.10 `reload` без catch.** `reload = async () => setItems((await getMedia())||[])` (`Watchlist.jsx:87`) has no error handling; a failed post-mutation refresh becomes an unhandled rejection and the UI keeps stale data silently. Confirmed by read.
- 🔵 **11.11 Багато довгих карток з pre-wrap/break-word.** Layout-only; not stress-tested.

## Confirmed issues, ordered by severity

1. 🔴 **9.9 Orphaned return-reminder** — deleting a scheduled library book's reading event in the calendar cascade-deletes the book but leaves its `media_return` reminder behind (`TaskService.DeleteTaskAsync` never clears `ReturnTaskId`). PoC `03-cascade-orphan.mjs`.
