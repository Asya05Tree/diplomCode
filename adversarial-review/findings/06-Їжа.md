## 1. Фронтенд — сторінка, вкладки, логіка

**1.1 Forbidden-страви витікають усюди, крім «Страви»** — 🔴 CONFIRMED
Evidence: hard-hide lives ONLY in `visibleRecipes` (`Food.jsx:140 if (recipe.health?.forbidden) return false`). `favoriteRecipes = recipes.filter(... selected.includes)` (`Food.jsx:266`) has NO forbidden filter → forbidden dish shows in «Обрані», menu picker (`:559-576`), and «Меню» tab via `recipeMap[id]` (`:350`). Server ships forbidden recipes too (see 7.3).
Repro: `04-overview-and-recipe-authz.mjs` → `After setting Forbidden on common tags: 6/6 recipes are health.forbidden` and `Forbidden recipe STILL in overview: id=1 "Борщ" ... ingredients=6 steps=4`. A forbidden recipe that was favorited/added to menu renders everywhere outside the dishes feed.
Impact: safety invariant (spec §2.3/§4.6: forbidden fully hidden) broken; a user with a hard allergy restriction still sees/plans/cooks the forbidden dish.

**1.2 `recipes.length` counts ALL recipes incl. forbidden** — 🟠 CONFIRMED
Evidence: tab meta uses `recipes.length` (`Food.jsx:307`) while the feed uses `visibleRecipes` (forbidden-filtered, `:137-146`). Counter > visible rows.
Impact: misleading counter.

**1.3 Menu stores `recipeId`, not a snapshot; dead ids counted** — 🟡 CONFIRMED
Evidence: `recipeMap[id]` → `if (!r) return null` (`Food.jsx:350-351`) silently drops a vanished recipe chip, but `menuCount` (`:267`) still counts the dead id.
Impact: counter/visible mismatch after seed/version change.

**1.4 `addToMenu` allows duplicates in one day** — 🟡 CONFIRMED
Evidence: `setMenu(... [...prev[day], recipeId])` (`Food.jsx:189-192`), no `includes` guard.
Impact: same dish repeats in a day.

**1.5 «Додати страву» disabled when no favorites, but existing chips persist** — 🟡 CONFIRMED
Evidence: button `disabled={favoriteRecipes.length === 0}` (`Food.jsx:373`); chips come from `menu` state which is independent of `selected`. Unticking all favorites freezes old menu chips.
Impact: stale menu that can no longer be edited/extended.

**1.6 Ticking «обране» also opens the cooking modal** — 🟡 CONFIRMED
Evidence: `handleToggleFavorite` → `if (willSelect) openCooking(recipe)` (`Food.jsx:207`). Untick does nothing. Double, asymmetric action.
Impact: surprising UX.

**1.7 Photo click opens cooking; checkbox `stopPropagation`** — ⚪ CONFIRMED
Evidence: `Food.jsx:440-441` (`onClick openCooking` on photo div, `onClick stopPropagation` on label).
Impact: easy accidental modal open.

**1.8 Tab switch does not reset open Drawers/cooking modal** — ⚪ CONFIRMED
Evidence: `setTab` (`:292` etc.) never clears `favoritesOpen`/`addStockOpen`/`cooking`/`menuPickDay`; these render as overlays regardless of tab.
Impact: potential "ghost" panels across tabs.

## 3. Валідація вводу, стани (loading/error/empty)

**3.1 No rollback on mutation failure (unhandled rejection)** — 🟠 CONFIRMED
Evidence: `handleStockState` (`:160-177`), `handleAddStock` (`:179-182`), `handleToggleFavorite` (`:202-208`), `finishCooking` (`:230-249`) all do optimistic `setState` then bare `await api…` with no `try/catch`. On failure UI shows false state; `finishCooking` throw leaves `setCooking(null)` unreached → modal stuck.
Impact: client/server divergence, stuck modal, console unhandled rejections.

**3.2 Full-page error only on `getFoodOverview` failure; no retry** — 🟠 CONFIRMED
Evidence: finance/shopping have `.catch` fallbacks (`:81-82`); only overview rejection sets `error` (`:99-104`); error screen is plain text, no retry button (`:258-264`).
Impact: user must hard-reload.

**3.3 `balance = 0` fallback → range {0,0} hides most recipes in «Все»** — 🟡 CONFIRMED
Evidence: finance fallback `{balance:0}` (`:81`) → `setRange({from:0,to:0})` (`:95`); filter `missingCost >= 0 && <= 0` (`:144`) shows only zero-cost recipes.
Impact: near-empty feed with no explanation when Finance is unavailable.

**3.4 Unknown price treated as 0** — 🟡 CONFIRMED
Evidence: `missingCost = missing.reduce((s,p)=>s+(p.personalPrice||0),0)` (`:125`).
Impact: expensive price-less ingredient shows «~0 грн», always passes budget filter.

**3.5 `clamp` breaks with negative balance** — 🟡 CONFIRMED (theoretical)
Evidence: `Math.min(Math.max(0,v), balance)` (`:148`) returns negative if `balance<0`.
Impact: broken range if Finance ever returns a negative balance.

**3.6 Empty states present and sensible** — ⚪ REFUTED (as defect)
Evidence: `emptyRecipes`/`menuNoFavorites`/`menuDayEmpty`/`favoritesEmpty` all wired (`:324,347,428,560`). Minor: `emptyRecipes` text only hints at budget.

**3.7 Stock search no debounce** — ⚪ CONFIRMED
Evidence: `:285` filter on every keystroke.

## 8. Безпека (XSS у назвах, масове призначення)

**8.1 Stored unsanitized content in user product names** — 🟠 CONFIRMED
Evidence: `AddStockByNameAsync` stores name as-is (`RecipeService.cs:161`). Repro `02`: `XSS payload: HTTP 200 ... stored verbatim? true` (`<img src=x onerror=alert(1)>`). React escapes on render, but the payload persists for JSON export / future `dangerouslySetInnerHTML` / reports / logs.
Impact: stored-content risk on any non-React surface.

**8.2 Garbage & near-duplicate products in the dictionary** — 🟠 CONFIRMED
Evidence/Repro `02`: 8192-char name stored; `"Дубль…"` vs `"Дубль…."` are DISTINCT products (punctuation not normalized); emoji/control chars stored. NOTE: `Trim()`+`ToLower()` DO fold trailing space and case (that part of the checklist claim is refined — whitespace/case dups do NOT occur; punctuation/length/charset do).
Impact: DB bloat + polluted «Додати запаси» search.

**8.3 Mass-assignment of stock state** — ⚪ REFUTED (safe)
Evidence: `State` white-listed (`:123`); `AddShoppingItemRequest.Section` white-listed (`ShoppingService.cs:125`). Missing `State` → framework 400 (`required`). No extra bound fields.

**8.4 Shopping `productId` not validated for existence** — 🟡 CONFIRMED
Evidence: `AddItemAsync` (`ShoppingService.cs:122-143`) never validates productId. Repro `03`: bogus productId `99999999` → `HTTP 500` (unhandled DB FK violation — ungraceful, but DB FK prevents bad data). Products are shared/system so cross-user ownership is N/A.
Impact: 500 instead of a clean 400.

**8.5 `window.confirm` with `{name}`** — ⚪ REFUTED (plain text, safe).
