КОРОТКО
-------
Застосунок переведено з тимчасового зберігання у браузері (localStorage /
псевдо-БД) на справжню базу даних MySQL + бекенд на C# (ASP.NET Core).
Довідники (ліки, інгредієнти, взаємодії) завантажуються з офіційних джерел
скриптами-імпортерами. Усі модулі прив'язані до акаунта користувача.


ЯК ЗАПУСТИТИ / ДЕ ДИВИТИСЬ БАЗУ
-------------------------------
1. Подвійний клік по start-all.ps1 (або: правою кнопкою -> Виконати з PowerShell).
   Він підніме: MySQL + phpMyAdmin (перегляд БД) + backend + frontend і відкриє
   у браузері сайт і базу.
2. Адреси:
     - Сайт:               http://localhost:5173
     - Перегляд БД:        http://localhost:8080   (phpMyAdmin, входить сам,
                           зліва всі таблиці, зверху вкладки Структура/SQL/…)
     - Перевірка backend:  http://localhost:5080/api/health
3. Якщо таблиці-довідники порожні — заповнити даними:
        cd server
        dotnet run -- import-all
4. Якщо змінювали схему БД — застосувати міграції:
        cd server
        dotnet ef database update

БАЗА ДАНИХ ТА БЕКЕНД
  - 27 нових таблиць (MySQL) по всіх модулях, прив'язані до користувача,
    двомовні довідники (NameUk / NameEn). Міграція застосована.
  - C# API для всіх модулів за єдиними конвенціями проекту (JWT, user-scoping).
  - Рушій правил (RuleEngine): перевіряє перетин тегів продукту/страви з
    обмеженнями користувача з урахуванням ієрархії тегів (обмеження «молочне»
    ловить і «лактозу», і «сир»).

ІМПОРТ ДОВІДНИКІВ З ОФІЦІЙНИХ ДЖЕРЕЛ (server/DataImport, dotnet run -- import-all)
  - ЛІКИ — Державний реєстр ДРЛЗ (data.gov.ua): 2038 безрецептурних карток,
    лише побутові форми, згорнуті дублі; беремо торгову назву + діючу речовину
    (МНН) + форму. 259 діючих речовин з кодами АТС.
  - СУМІСНІСТЬ — DDInter 2.0 (ліцензія CC BY-NC-SA): 514 взаємодій «ліки-ліки».
  - ІНГРЕДІЄНТИ — USDA FoodData Central: продукти з тегами алергенів, прив'язані
    до рецептів; українська специфіка додана вручну.

ПЕРЕЙМЕНУВАННЯ
  - Розділ «Аптечка» -> «Здоров'я» (uk) / «Health» (en).

ЇЖА
  - Довідники продуктів і рецептів + стан користувача (запаси, обрані страви,
    готовка) — усе з БД. Наявність інгредієнтів і статус здоров'я страв
    рахуються через рушій правил. Дві вкладки: Страви / Запаси (з категоріями).

ЗДОРОВ'Я (аптечка + хвороби)
  - Аптечка користувача: пошук по довіднику з 2038 ліків, додавання, стан.
  - Взаємодії в картці — з DDInter; формулювання лише «у базі не знайдено
    взаємодій» (ніколи «конфліктів немає») + підпис, що дані довідкові й не
    замінюють лікаря. Колір за рівнем ризику.
  - Хронічні захворювання: додавання зі свитчем «впливає на їжу»; якщо так —
    поле тега + рівень (не можна / небажано) -> одразу стає правилом і фільтрує
    страви. Видалення захворювання прибирає і правило.
  - Колонку «Термін» прибрано (ненав'язливо, як просили).
  - Категорії ліків = форми випуску; пластир/бинт/термометр тепер у групі
    «Медичні вироби», а не окрема категорія з одного елемента.

СПИСОК ПОКУПОК (за повною специфікацією spisok-pokupok.md)
  - Розділи (Продукти / Аптека / Інше), вибір розділу й категорії над списком.
  - Підказки «Часто купуєте» з історії за 90 днів.
  - Відмітка покупки одним жестом: закриває позицію -> поповнює запаси ->
    записує особисту ціну -> створює витрату у «Фінансах».
  - Альтернатива: «загальна сума чека» з розкладкою залишку по позиціях.
  - Фільтр докупівлі: за кількістю позицій, поки цін мало; за сумою, коли
    цін достатньо. Жодних заздалегідь прописаних цін.
  - Кнопка «Запланувати похід у магазин» -> створює задачу в календарі.

ФІНАНСИ
  - Баланс, ліміти (тиждень/місяць), транзакції (додавання/видалення/список).

ЦИКЛ

    регулярний, рядок «цикл нерегулярний» за великого розкиду), налаштування.

===============================================================================
  ЗРОБЛЕНО ЧАСТКОВО / В ПРОЦЕСІ
===============================================================================

  - НАВЧАННЯ, вкладка «Розклад»: поки лише перегляд. Пари зберігаються як
    правила повторення (ті самі цикли тижнів/винятки, що й у планувальнику,
    з позначкою moduleCode="study"), тож розклад РЕДАГУЄТЬСЯ через звичайні
    повторювані задачі в календарі, але окремого редактора розкладу на самій
    сторінці «Навчання» ще немає.

  - ПАРАМЕТРИ ЛЮДИНИ (зріст/вага/рік народження): показуються на сторінці
    «Здоров'я» і зберігаються в БД; редагування вже працює через API
    (PUT /api/health-profile), але окремої форми редагування на сторінці ще
    не додано (значення «—», поки не заповнені).

  - ЦИКЛ, «перевірка запасів до дати» (прокладки/знеболювальне/солодке зі
    spec §3.7): прогноз і записи працюють, але окремої перевірки запасів до
    прогнозованої дати поки немає (не додано відповідний ендпоінт).

  - ПІДКАЗКИ «Часто купуєте» працюють, але список порожній, поки користувач
    не почне відмічати покупки (історія накопичується з часом) — це за задумом.

  - Взаємодії «ліки-їжа» як окремий довідник — див. обмеження нижче.


===============================================================================
  ТЕХНІЧНІ ОБМЕЖЕННЯ (дані / джерела)
===============================================================================

  - DDInter 2.0 у вивантаженні містить ЛИШЕ взаємодії «ліки-ліки». Взаємодій
    «ліки-їжа» у завантажуваному наборі НЕМАЄ — тому їх не імпортуємо.
    Обмеження щодо їжі (алергії/хвороби <-> продукти) повністю покриває
    окремий рушій правил на тегах (профіль користувача <-> теги продукту).

  - У ліків NameEn = NameUk: Державний реєстр не містить англійських ТОРГОВИХ
    назв (англійською є лише діюча речовина — МНН). Це чесно, не вигадуємо.

  - Комбіновані препарати (у реєстрі «Comb drug», «Mono», «…combinations»)
    не мають єдиної діючої речовини -> для них взаємодії не показуються.
    2038 карток посилаються на 259 реальних однокомпонентних речовин.

  - Рівні взаємодій: частина — «Unknown» (так у даних DDInter).

  - Довідник ліків навмисно обмежений: лише безрецептурні + 5 побутових форм
    (таблетки, капсули, сиропи, мазі, краплі).

  - Довідник інгредієнтів визначається рецептами (зараз ~26 продуктів) і
    розширюється в міру додавання рецептів/продуктів — це не весь USDA FDC.

  - Ціни особисті й стартують порожніми (жодних заздалегідь прописаних цін).
    Поки цін мало, підсумки списку показуються діапазоном / за кількістю.

  - Сирі датасети (ДРЛЗ, DDInter, USDA FDC) качаються у server/seed-data і
    НЕ комітяться в git (.gitignore). Повторне заповнення: dotnet run -- import-all.
